## CogboxException

Base exception for all Cogbox SDK errors.

Subclasses map to specific HTTP status codes and allow callers to catch
precise failure conditions without string-parsing error messages:
```java
try {
Sandbox sandbox = cogbox.sandbox().get("nonexistent-id");
} catch (CogboxNotFoundException e) {
// sandbox does not exist
} catch (CogboxAuthenticationException e) {
// invalid API key
} catch (CogboxException e) {
// other SDK error
}
```

## CogboxAuthenticationException


## CogboxConflictException

Raised when an operation conflicts with the current state (HTTP 409).

Common causes: creating a resource with a name that already exists,
or performing an operation incompatible with the resource's current state.
```java
try {
cogbox.snapshot().create(params);
} catch (CogboxConflictException e) {
System.err.println("A snapshot with this name already exists");
}
```

## CogboxConnectionException

Raised for network-level connection failures (no HTTP response received).

Raised when the SDK cannot reach the Cogbox API due to network issues
such as DNS failure, connection refused, or TLS errors.
```java
try {
cogbox.sandbox().create();
} catch (CogboxConnectionException e) {
System.err.println("Cannot reach Cogbox API: " + e.getMessage());
}
```

## CogboxServerException

Raised for unexpected server-side failures (HTTP 5xx).

These are typically transient and safe to retry with exponential backoff.
```java
try {
cogbox.sandbox().create();
} catch (CogboxServerException e) {
System.err.println("Server error (status " + e.getStatusCode() + "), retry later");
}
```

## CogboxValidationException

Raised for semantic validation failures (HTTP 422).

Raised when the request is well-formed but the values fail business logic
validation (e.g., unsupported resource class, invalid configuration).
```java
try {
cogbox.sandbox().create(params);
} catch (CogboxValidationException e) {
System.err.println("Validation failed: " + e.getMessage());
}
```
