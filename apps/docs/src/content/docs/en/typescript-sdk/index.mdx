The Cogbox TypeScript SDK provides a powerful interface for programmatically interacting with Cogbox Sandboxes.

## Installation

Install the Cogbox TypeScript SDK using npm:

```bash
npm install @cogbox/sdk
```

Or using yarn:

```bash
yarn add @cogbox/sdk
```

## Getting Started

### Create a Sandbox

Create a Cogbox Sandbox to run your code securely in an isolated environment. The following snippet is an example “Hello World” program that runs securely inside a Cogbox Sandbox.

```typescript
import { Cogbox } from '@cogbox/sdk'

async function main() {
  // Initialize the SDK (uses environment variables by default)
  const cogbox = new Cogbox()

  // Create a new sandbox
  const sandbox = await cogbox.create({
    language: 'typescript',
    envVars: { NODE_ENV: 'development' },
  })

  // Execute a command
  const response = await sandbox.process.executeCommand('echo "Hello, World!"')
  console.log(response.result)
}

main().catch(console.error)
```

## Configuration

The Cogbox SDK can be configured using environment variables or by passing options to the constructor:

```typescript
import { Cogbox } from '@cogbox/sdk';

// Using environment variables (COGBOX_API_KEY, COGBOX_API_URL, COGBOX_TARGET)
const cogbox = new Cogbox();

// Using explicit configuration
const cogbox = new Cogbox({
  apiKey: 'YOUR_API_KEY',
  apiUrl: 'https://cogbox.pazity.com/api',
  target: 'us'
});
```

For more information on configuring the Cogbox SDK, see [configuration](/docs/en/configuration).

## Multiple runtime support

The TypeScript SDK ships as a dual ESM/CJS package and works out of the box in **Node.js**, **Bun**, **Next.js**, **Nuxt.js**, **Remix**, **Vite SSR**, **AWS Lambda**, and **Azure Functions** without any extra configuration.

For **Cloudflare Workers**, set the Node.js compatibility flag in your `wrangler.toml`:

```toml
compatibility_flags = ["nodejs_compat"]
```

For **Deno**, install with `deno add npm:@cogbox/sdk` or import directly with the `npm:` specifier:

```typescript
import { Cogbox, Image } from 'npm:@cogbox/sdk'
```

For **browser apps with Vite** (or any browser bundler), install [`vite-plugin-node-polyfills`](https://www.npmjs.com/package/vite-plugin-node-polyfills) and add it to your `vite.config.ts`:

```typescript
import { defineConfig } from 'vite'
import { nodePolyfills } from 'vite-plugin-node-polyfills'

export default defineConfig({
  plugins: [nodePolyfills({ globals: { Buffer: true, process: true, global: true } })],
})
```

The SDK uses Node's `Buffer` for binary data (downloaded files, multipart bodies). Browsers don't ship `Buffer`, so the polyfill provides it. Without it, basic operations like `Image.base()` and `cogbox.list()` still work, but methods that handle binary payloads (`fs.downloadFile`, `fs.downloadFiles`) will throw.

Some runtimes don't expose the full set of Node.js APIs (browsers and edge runtimes have no filesystem, no `crypto`, etc.). Methods that depend on those APIs throw a clear runtime error instead of silently producing wrong results.
